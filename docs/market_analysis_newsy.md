> Дата анализа: 13 июля 2026 г.  
> Стек: Next.js 15 · React 19 · PostgreSQL / Prisma · Supabase · ЮKassa · Three.js

---

## 1. Что такое NEWSY (как я понял проект)

NEWSY — это **платформа-конструктор челленджей** (ЧИ — «Челлендж/Инициатив»):
- Организаторы (бренды, блогеры, НКО, госструктуры) создают многоэтапные активности
- Участники выполняют этапы, загружают доказательства, получают награды и достижения
- Платформа берёт комиссию за публикацию ЧИ + процент от платного участия
- Геймификация: очки, уровни, достижения, рейтинги
- Монетизация: подписка для организаторов, платное участие, реферальная программа

**Ключевая уникальность:** конструктор многоэтапных активностей + кооперативные механики + интерактивная карта.

### 2.3 Рыночный контекст (русскоязычный)

**Тренды в пользу NEWSY:**
- 📈 Рост UGC-маркетинга: бренды активно платят за контент от аудитории
- 📈 Замещение западных SaaS: ушли Typeform, Kahoot, Slack Workflow
- 📈 Рост НКО и социальных инициатив — им нужен инструмент
- 📈 Госпрограммы (молодёжная политика, ЗОЖ, патриотические активности)
- 📈 B2B-геймификация HR: корпоративные марафоны, конкурсы сотрудников

**Угрозы:**
- ⚠️ VK экосистема имеет VK Марафоны и инструменты для конкурсов
- ⚠️ Telegram боты заменяют сложные платформы для простых активностей
- ⚠️ Высокий порог создания контента для организаторов без шаблонов

## 3. Анализ текущего состояния проекта

### 3.1 Что сделано хорошо ✅

| Область | Оценка |
|---------|--------|
| Технический стек | Современный (Next.js 15, React 19) — плюс |
| Схема БД | Очень продуманная: RBAC, ChallengeOrganizer, AccountType, enum'ы |
| Модульная архитектура | Feature-modules (identity, challenges, payments) — правильно |
| Безопасность | После исправлений: HMAC webhook, PENDING статус, async pbkdf2 |
| Многоступенчатые ЧИ | Модель Step + StepProgress — правильная основа |
| Юридическая база | AccountType (ИП/ООО/АО/Самозанятый) в схеме — дальновидно |
| Платежи | ЮKassa — правильный выбор для РФ |

### 3.2 Критические пробелы (блокируют MVP) 🔴

1. **Email-верификация не отправляется** — структура таблицы `EmailVerificationToken` есть, но письмо не шлётся
2. **Сброс пароля — заглушка** — пользователь не может восстановить аккаунт
3. **Rate limiting только in-memory** — не работает в Vercel (serverless)
4. **Конструктор ЧИ для организатора** — форма создания неизвестна (нужно проверить наличие UI)
5. **Нет онбординга** — как организатор создаёт первый ЧИ?

### 3.3 Продуктовые проблемы 🟠

| Проблема | Влияние |
|----------|---------|
| UI лендинга — только каталог, нет hero-секции с ценностным предложением | Новые пользователи не понимают что это |
| Нет профиля организатора для участников | Участник не может узнать кто организует ЧИ |
| Отсутствует реальная карта (только в README) | Заявленная фича не реализована |
| Нет push/email-уведомлений | Участник не знает о начале ЧИ |
| Нет соцсетей / шеринга | Нет вирального эффекта |
| `isCooperative` в UI без механики | Вводит в заблуждение |
| Нет дашборда организатора с аналитикой | Ключевой для монетизации |

## 5. Что убрать / упростить

### 5.1 Убрать сейчас

| Элемент | Причина |
|---------|---------|
| `isCooperative` из UI | Механика не реализована — вводит в заблуждение |
| `rewardPoints` из UI этапов | Продуктово решено убрать баллы (docx) |
| Кнопка «Кабинет» из шапки | Дублирует «Профиль» (docx, п.1) |
| Уровни / Опыт из профиля | Упростить до Достижений + Наград (docx, п.2) |
| Three.js (3D-графика) | Тяжёлая зависимость (+500KB bundle). Если не используется активно — убрать |

### 5.2 Переосмыслить

| Элемент | Проблема | Решение |
|---------|----------|---------|
| Публикация ЧИ стоит 1000 ₽ по умолчанию | Барьер для НКО и новых организаторов | Freemium: 1 ЧИ бесплатно |
| `publishPrice` hardcoded | Жёсткая цена плохо масштабируется | Гибкие тарифы по подписке |
| Самописная аутентификация (HMAC + cookie) | Сложно поддерживать | Рассмотреть NextAuth v5 или Supabase Auth |
| In-memory rate limiting | Не работает в serverless | Upstash Redis (уже упомянут в .env.example) |
| Unsplash fallback в API | Внешняя зависимость | Placeholder SVG или локальный default |

## 6. Что изменить в корне

### 6.1 🔄 Концепция главной страницы

**Сейчас:** Каталог челленджей сразу  
**Проблема:** Новый пользователь не понимает что это за платформа и зачем ей пользоваться

**Нужно:** Разделить на два режима входа
```
/ → Лендинг (для незалогиненных) с hero + объяснением + примерами + CTA
/explore → Каталог (после авторизации или как вторичный CTA)
```

### 6.2 🔄 Архитектура ролей

**Сейчас:** «Пользователь» — единая роль, может быть и участником, и организатором  
**Проблема:** UX сильно разный для этих двух ролей

**Нужно:** Явный выбор при регистрации
```
Я хочу → [Участвовать в челленджах] / [Запускать челленджи]
```
И два разных дашборда соответственно.

### 6.3 🔄 Модель монетизации

**Сейчас:** Разовая оплата публикации ЧИ (1000 ₽) + % от участия  
**Проблема:** Разовый платёж не создаёт recurring revenue; % от участия сложно собирать

**Нужно рассмотреть:** Подписочная модель для организаторов + freemium для участников  
```
Участники: всегда бесплатно (монетизация через платные ЧИ)
Организаторы: подписка по тарифам (Стартер/Бизнес/Корпоратив)
```

### 6.4 🔄 Верификация контента

**Сейчас:** Модерация ЧИ через admin-панель (ручная)  
**Проблема:** Не масштабируется; нет защиты от спама/мошенничества

**Нужно:** 
- Auto-approve для верифицированных организаторов
- Жалобы участников на ЧИ
- Escrow-механика для платных ЧИ (деньги держатся до завершения)

### 6.5 🔄 Технически: заменить кастомную auth

**Сейчас:** HMAC + cookie, дублирование логики в middleware и session.ts  
**Риски:** Сложно поддерживать, edge runtime vs Node.js несовместимость

**Рекомендация:** Перейти на **Supabase Auth** (уже используется Supabase Storage) — это избавит от дублирования, даст OAuth (VK, Yandex), MFA и refresh tokens из коробки.

## 9. Конкурентный вывод

NEWSY находится в **правильной нише** — self-service платформа для создания и управления многоэтапными активностями в России. Прямых конкурентов с таким же набором функций (конструктор + геймификация + монетизация + публичный каталог) **на русском рынке нет**.

Главный риск — не конкуренты, а **время до рынка**. Чем быстрее будет рабочий MVP с 5–10 реальными ЧИ, тем больше шансов занять нишу до появления аналогов от VK или Яндекса.

**Самое важное сейчас:** запустить конструктор ЧИ и привлечь первых 3–5 организаторов (лучше — НКО или спортивные клубы, они менее требовательны по SLA).
